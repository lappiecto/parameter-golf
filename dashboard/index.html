Experiment Controls
This is your workbench. Each slider controls a different aspect of the model you're training. Tweak these values, then hit Launch to train a model and see how it scores. Think of it like tuning a racing car — every setting affects performance.
⚙ Architecture
These settings define the shape and size of your neural network. A transformer is made of stacked layers, each containing attention (which finds patterns between tokens) and an MLP (which processes those patterns). More layers and wider dimensions mean a smarter model — but it also gets bigger, and you only have 16MB to work with.
9
How many transformer blocks are stacked on top of each other. Each layer gives the model another chance to refine its understanding. More layers = deeper reasoning, but each one adds about 2.6 million parameters (at dim=512). The baseline uses 9, the competition leaders use 10-11.
Leaderboard impact: going from 9 to 10 layers gained ~0.003 BPB
512
The width of every hidden representation inside the model. Think of it as the "bandwidth" of information flowing through each layer. 512 means every token is represented as a vector of 512 numbers. Doubling this roughly quadruples the total parameter count, so 512 is the sweet spot for fitting under 16MB.
8
Attention is how the model decides which other tokens in the sequence matter for predicting the next one. Multiple heads let it look for different kinds of relationships simultaneously — one head might track grammar, another might track topic, etc. 8 heads at dim=512 gives each head 64 dimensions to work with.
4
Grouped Query Attention is a trick to save parameters. Instead of giving every attention head its own Key and Value projections, multiple heads share them. With 8 query heads and 4 KV heads, each KV pair is shared by 2 query heads. This saves ~25% of attention parameters with minimal quality loss.
2
The MLP (feed-forward network) in each layer expands the representation to a wider hidden dimension, applies a nonlinearity, then compresses it back. This multiplier controls how wide that expansion is. The MLP is where most of the model's "knowledge" is stored — wider = more capacity. Every competition leader uses 3x.
Leaderboard impact: going from 2x to 3x MLP gained ~0.01 BPB
1024
How many unique tokens the model knows. A 1024-token vocabulary is tiny by LLM standards (GPT-4 uses ~100k), but it means the embedding table only takes vocab_size x model_dim parameters. Larger vocab = more efficient tokenisation (fewer tokens per sentence) but costs more parameters in the embedding. Changing this requires re-tokenising the training data, so it's an advanced move.
⚡ Training
These control how the model learns. Training works by showing the model text, asking it to predict the next token, measuring how wrong it was (the loss), and then adjusting its weights to be less wrong next time. Each "iteration" is one such update step. More iterations = more learning, up to a point where the model starts memorising instead of generalising.
200
Number of weight-update steps. The competition runs ~20,000 iterations on H100 GPUs. Locally on your M4 Max, keep this low (200-500) for quick experiments. You won't match H100 quality locally, but you can see which settings trend in the right direction.
1024
How many tokens the model sees at once during training. Longer sequences let the model learn longer-range patterns (like how a paragraph connects to its introduction). This was one of the easiest wins on the leaderboard — going from 1024 to 2048 tokens gave a significant improvement because the model could use more context when predicting.
Leaderboard impact: 1024 to 2048 gained ~0.02 BPB, 4096 added another ~0.005
8192
Total tokens processed per training step across all gradient accumulation steps. Larger batches give more stable gradient estimates (less noise in the learning signal), but require more memory. The H100 default is 524,288 tokens per step. Locally, use 8k-32k depending on your available memory.
20
The learning rate starts at zero and linearly ramps up over this many steps. This prevents the randomly-initialised model from making huge, destructive weight updates in the first few steps. 20 steps is a good default — enough to stabilise without wasting training time.
1200
Near the end of training, the learning rate gradually drops to zero over this many iterations. This lets the model "settle" into a good solution instead of bouncing around. Think of it like slowing down as you approach a parking spot. Competition leaders use 3000 warmdown iterations for smoother convergence.
Leaders use warmdown=3000 for better final convergence
0
Caps the maximum size of gradient updates. If a training example produces an unusually large gradient, clipping prevents it from destabilising the model. Set to 0 to disable. The current leader uses 0.3. This is a safety net — not always needed but can help with stability.
600
Hard time limit for training. The competition enforces 600 seconds (10 minutes) on 8xH100s. Locally you can set this higher if you want longer runs, or lower for quick iterations. Training stops when either this limit or the iteration count is reached, whichever comes first.
📈 Optimiser
The optimiser is the algorithm that actually updates the model's weights based on the gradients. This model uses two different optimisers: Muon for the big matrix weights (attention and MLP layers) and Adam for everything else (embeddings and small scalars). Muon is special — it orthogonalises gradients before applying them, which helps the model learn more efficiently in this constrained setting.
0.05
Learning rate for the token embedding table (used by Adam, not Muon). The embedding converts token IDs into vectors the model can process. Because the embeddings are tied (shared between input and output), this single table does double duty, so its learning rate needs careful tuning.
0.04
Learning rate for all the big weight matrices (Q, K, V, output projections, MLP layers), optimised by Muon. This is the most important learning rate because these matrices contain most of the model's parameters. Competition leaders dropped this from 0.04 to 0.02 for more stable training.
Leaders use matrix_lr=0.02 for better stability
0.04
Learning rate for small scalar/vector parameters like layer scales, attention gains, and residual mixing weights. These are tiny but important — they control how much each layer contributes to the final output.
0.95
How much Muon remembers from previous gradient updates. Higher momentum means smoother, more consistent updates because the optimiser carries more "memory" of past gradients. This prevents the model from zigzagging during training. Every leader bumped this from 0.95 to 0.99 — one of the easiest and most impactful tuning changes.
Leaderboard: 0.95 to 0.99 gave measurable BPB improvement
1.5
Initial scaling factor for the query vectors in attention. This controls how "sharp" the attention distribution starts out. Higher values make attention more focused from the start, lower values make it more diffuse. The learnable gain per head allows the model to adjust this during training.
30
Caps the maximum logit value using tanh(x/cap)*cap. This prevents the model from becoming overconfident in its predictions, which can cause training instability. 30 is a sensible default — low enough to regularise, high enough not to hurt expressiveness.
🎉 Advanced Techniques (SOTA)
These are the techniques used by the competition leaders that go beyond basic hyperparameter tuning. SmearGate and BigramHash are architecture changes that give the model bigram-level awareness before it enters the transformer layers. Orthogonal init and weight decay are training improvements. Together they're worth ~0.03-0.05 BPB.
1
Blends each token's embedding with the previous token's embedding using a learned per-dimension gate. Initialised at 50/50 blend (sigmoid(0) = 0.5). Gives the model bigram-level context before the first transformer layer — like a cheap lookahead that helps disambiguate tokens. Present in every top-5 submission. 1 = on, 0 = off.
Present in all top-5 submissions
4096
Hashes consecutive token pairs into a lookup table with this many buckets. Each pair maps to a learned 128-dim embedding that's added to the token representation. More buckets = fewer hash collisions = more distinct pair representations. The leader uses 10240. Set to 0 to disable entirely.
Leader uses 10240; going from 4096 to 10240 gained ~0.002 BPB
128
Embedding dimension for the bigram hash table. These get projected to the model dimension (512) via a learned linear layer. 128 is what all leaders use — large enough to be expressive, small enough to not dominate the parameter budget.
0.04
Decoupled weight decay applied to all Muon-optimised matrix parameters. Shrinks weights toward zero each step, which keeps the weight distribution tight. This helps both generalisation (prevents overfitting) and post-training quantisation (tighter distributions compress better into int8/int6). The leader uses 0.04.
Leader uses 0.04; helps both quality and compression
6
Bit depth for MLP weight quantisation after training. Int8 (127 levels) is the safest. Int6 (31 levels) compresses ~1.5x better. Int5 (15 levels) compresses ~1.9x better but loses more precision. MLP weights tolerate aggressive quantisation because relu² creates sparse activations — most weights barely matter. The SOTA leader uses int5 for MLPs, freeing enough bytes to fit an extra layer.
Int5 MLP saves ~1.86MB vs int6, funding a 10th layer
6
Bit depth for attention weight quantisation. Attention weights are more precision-sensitive than MLP weights because they control the sharp attention patterns that determine which tokens attend to which. The SOTA leader uses int6 here — aggressive enough to save space, precise enough to preserve attention quality.
Leader uses int6 for attention weights
64
During final evaluation, instead of chopping the validation set into independent chunks, we slide a window forward by this many tokens. Each scored token gets (seq_len - stride) tokens of context. With stride=64 and seq_len=2048, that's 1984 tokens of context per scored position vs ~1024 average without sliding. This is a FREE BPB improvement — no retraining needed. Set to 0 to disable.
Worth ~0.03 BPB for free (eval-only, no retraining)
1
Stochastic Weight Averaging: during the last portion of warmdown, snapshot the model every N steps, then average all snapshots before final evaluation. The averaged model is almost always better than any individual checkpoint because it smooths out noise from individual training steps. Like asking 20 versions of the model for consensus. 1 = on, 0 = off.
Worth ~0.005-0.01 BPB
0.4
When to start collecting SWA checkpoints, as a fraction of the warmdown LR multiplier. 0.4 means start collecting when the learning rate has decayed to 40% of peak. Lower values = more checkpoints collected = smoother average but includes earlier, less-converged snapshots. The leader uses 0.4.
50
How often to collect a checkpoint during the SWA window. Every 50 steps is what the leader uses. Smaller values = more checkpoints = smoother average but more memory usage.
📊 Evaluation
These control how and when the model is tested against the validation set during training. The validation set is a held-out portion of text the model never sees during training. Evaluating on it tells us how well the model generalises to new text — which is ultimately what the competition scores.
8192
How many tokens to evaluate at once during validation. Larger values are more efficient but use more memory. The full validation set is always evaluated — this just controls the batch size for processing it.
0
Run validation every N training steps. Set to 0 to only validate at the end (faster for quick experiments). Set to e.g. 200 if you want to watch the BPB improve over time during training. Each validation run takes a while, especially on MLX, so don't set this too low.
200
Print a training loss summary line every N steps. More frequent logging gives you finer-grained visibility into how training is progressing, but very frequent logging can slightly slow things down.
